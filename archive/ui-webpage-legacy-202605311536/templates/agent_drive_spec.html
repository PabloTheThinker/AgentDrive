Agent Drive — Agent-Facing Contract

Minimal, stable surface for any process (model-backed, tool-using, or native) to act as a first-class Agent Drive participant.

1. Overview

Agent Drive is the substrate. Agents talk to it via:

  • HTTP + SSE (recommended for custom runtimes)
  • Native Python (import agentdrive — the same substrate the TUI, web UI, and swarms use)
  • LLM fallback mode (when no dedicated runtime is configured)
your agent (HTTP/SSE or native)
↓ POST /chat + stream
Agent Drive (Drive + genomes + KG + reconciliation + HealingFactor + durable jobs)
↓ optional
│ │ ▼ fallback ┌──────────────────┐ │ LLM provider │ │ (Anthropic etc) │ └──────────────────┘

2. runtime.json schema

Path: ~/.agentdrive/agents/<agent_id>/runtime.json. Permissions: 0600 (Agent Drive writes atomically).

kind: "http_sse" — primary path

{
  "kind": "http_sse",
  "url": "http://localhost:8081/chat",
  "auth_env": "CONDUCTOR_RUNTIME_TOKEN",
  "timeout_s": 120
}

auth_env names a process env var; Agent Drive reads its value and sends Authorization: Bearer <value>. Omit for unauthenticated endpoints. timeout_s defaults to 120.

kind: "model" — fallback

{
  "kind": "model",
  "provider": "anthropic",
  "model": "claude-sonnet-4.6"
}

Uses the operator's API key from ~/.agentdrive/.env. If runtime.json is absent, Agent Drive defaults to kind: "model" and resolves provider/model from the agent's providers.json allow-list.

3. HTTP + SSE protocol

What Agent Drive sends to your endpoint when a user posts a chat turn:

MethodPOST
Content-Typeapplication/json
AuthorizationBearer <auth_env value> (optional)
Body{"messages": [...], "agent_id": "<id>"}
Accepttext/event-stream

Each message in messages is {"role": "system" | "user" | "assistant", "content": "..."}. The first message is the composed system prompt (identity + substrate block). Your agent SHOULD respond text/event-stream with:

data: {"text": "first chunk"}

data: {"text": "next chunk"}

event: done
data: {}

On error, emit either an HTTP 4xx/5xx with a text body, or an SSE error event:

event: error
data: {"error": "rate limited"}

curl example

curl -N -X POST https://your-agent.example/chat \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer $TOKEN' \
  -d '{"messages":[{"role":"user","content":"hi"}],"agent_id":"conductor"}'

import json

app = FastAPI()

@app.post("/chat")
async def chat(req: Request):

    messages = body["messages"]

        # plug your model call here; yield SSE-shaped strings

            yield f"data: {json.dumps({'text': chunk})}\n\n"
        yield "event: done\ndata: {}\n\n"
    return StreamingResponse(stream(), media_type="text/event-stream")

4. Native Python integration (recommended for depth)

Any Python process can be a full peer of the substrate:

from agentdrive import AgentDrive, DriveQuery

with AgentDrive(name="my-substrate") as d:
    g = d.ingest({"framework": {"steps": [...]}, "manifest": {"id": "my-skill-v1"}})
    result = d.think("How do I ...", prefer_experience_layer=True)
    print(result.answer)
    print("Gaps:", [g.description for g in result.gaps])

The same Drive, ReconciliationRunner, HealingFactor, DurableJobSupervisor, and Genome objects power the TUI, web UI, and every role-specialized swarm. Your native agent sees exactly the same durable state.

5. Genomes are the unit of capability

Successful runs are decomposed into typed, versioned, content-addressed genomes. They carry:

  • framework steps (executable playbooks)
  • manifest (provenance, authors, evaluation scores)
  • page_type (for schema-pack boosts and experience layer routing)
  • optional experience-observation / daily-present / research-constitution payloads

Query them, fork them, promote them through quarantine gates, evolve them. The pool only grows stronger.

6. Trust boundaries (never optional)

Everything entering the live pool from outside — peer genomes, imported snapshots, third-party adapters — passes through quarantine.submit and the evaluator gate. trust_level only adjusts quorum; it never bypasses the gate.

This contract is stable. Changes are versioned through schema packs and experience layer evolution.
