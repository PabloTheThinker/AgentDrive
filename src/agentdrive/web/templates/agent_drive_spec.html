1. What Agent Drive is

Agent Drive is a substrate-grounded chat shell. The sidebar talks to the operator's own agent runtime over HTTP+SSE; Agent Drive is the transport, not the LLM. A model-provider fallback exists for agents that are bare LLM wrappers.

┌──────────┐ ┌──────────────────┐ ┌─────────────────┐ │ human │ ──▶ │ Agent Drive │ ──▶ │ agent runtime │ │ (web) │ ◀── │ sidebar + API │ ◀── │ (yours) │ └──────────┘ └──────────────────┘ └─────────────────┘ │ ▼ fallback ┌──────────────────┐ │ LLM provider │ │ (Anthropic etc) │ └──────────────────┘

2. runtime.json schema

Path: ~/.agentdrive/agents/<agent_id>/runtime.json. Permissions: 0600 (Agent Drive writes atomically).

kind: "http_sse" — primary path

{
  "kind": "http_sse",
  "url": "http://localhost:8081/chat",
  "auth_env": "ILO_RUNTIME_TOKEN",
  "timeout_s": 120
}

auth_env names a process env var; Agent Drive reads its value and sends Authorization: Bearer <value>. Omit for unauthenticated endpoints. timeout_s defaults to 120.

kind: "model" — fallback

{
  "kind": "model",
  "provider": "anthropic",
  "model": "claude-sonnet-4.6"
}

Uses the operator's API key from ~/.agentdrive/.env. If runtime.json is absent, Agent Drive defaults to kind: "model" and resolves provider/model from the agent's providers.json allow-list.

3. HTTP + SSE protocol

What Agent Drive sends to your endpoint when a user posts a chat turn:

MethodPOST
Content-Typeapplication/json
AuthorizationBearer <auth_env value> (optional)
Body{"messages": [...], "agent_id": "<id>"}
Accepttext/event-stream

Each message in messages is {"role": "system" | "user" | "assistant", "content": "..."}. The first message is the composed system prompt (identity + substrate block). Your agent SHOULD respond text/event-stream with:

data: {"text": "first chunk"}

data: {"text": "next chunk"}

event: done
data: {}

On error, emit either an HTTP 4xx/5xx with a text body, or an SSE error event:

event: error
data: {"error": "rate limited"}

curl example

curl -N -X POST https://your-agent.example/chat \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer $TOKEN' \
  -d '{"messages":[{"role":"user","content":"hi"}],"agent_id":"ilo"}'

Minimal Python FastAPI handler

from fastapi import FastAPI, Request
from fastapi.responses import StreamingResponse
import json

app = FastAPI()

@app.post("/chat")
async def chat(req: Request):
    body = await req.json()
    messages = body["messages"]
    async def stream():
        # plug your model call here; yield SSE-shaped strings
        for chunk in ["hello ", "from ", "my agent"]:
            yield f"data: {json.dumps({'text': chunk})}\n\n"
        yield "event: done\ndata: {}\n\n"
    return StreamingResponse(stream(), media_type="text/event-stream")

4. identity.md

Optional file at ~/.agentdrive/agents/<agent_id>/identity.md. Agent Drive composes the chat system prompt as:

You are <agent_id>, an agent on this Agent Drive.

<identity.md body>

<generic operator-facing instruction>

=== LIVE SUBSTRATE (read at start of this turn) ===
<substrate block>
=== END SUBSTRATE ===

For kind: "http_sse" agents, the composed system prompt arrives as the first system message in the POST body.

5. Substrate context

Agent Drive injects four slices of live state (best-effort — silent on missing data):

  • Dreams — most recent dream run + top promotion candidates per lane.
  • Genomes — top eight registered genomes with latest versions.
  • Reasoning ledger — most recent ten entries.
  • Drive ingest — last ten events from drive/ingest.jsonl.

Each substrate read is also emitted to the sidebar UI as a SubstrateRead event:

{
  "kind": "dreams" | "genomes" | "reasoning" | "drive_ingest" | "error",
  "path": "<relative path>",
  "summary": "<short human-readable summary>",
  "latency_ms": <int>,
  "payload": { ... }
}
